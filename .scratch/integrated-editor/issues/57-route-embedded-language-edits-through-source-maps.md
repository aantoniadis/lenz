## Answer

Merged in fec6f27 (branch work/editor-57-source-maps). Production routing in `crates/code-core/src/template.rs`: files ending `.erb`, `.rhtml` or `.haml` are templates; each tag's Ruby is copied byte for byte (a newline after each) and sent to Ruby LSP under the template's own URI and version as `languageId: ruby` (Ruby LSP's own ERB mode is not used); ERB is read as Rails' Erubi reads it (`<%-`, `-%>`, `=%>`, `<%==`; `<%#` and `<%%` are not Ruby; `%%>` in a code tag refused); `.html.erb`/`.htm.erb`/`.rhtml` markup goes to the HTML server as `languageId: html` with every tag masked by `_`; Haml is read line by line for the contexts ticket 04 mapped plus `.class`/`#id`, `-#` and `!!!`, any other construct leaving the template's Ruby unmapped with its line and reason. Positions convert in each server's negotiated encoding against its projection; scaffolding maps to nothing, and a template's own document refuses conversion (fails closed). The caret picks the server; Format Document, Organize Imports and file symbols go to the Ruby; a caret on delimiters, comments, Haml markup or non-HTML text asks nothing and says why. Every provider edit (completion and its extra edits, snippets, quick fixes, formatting, server-command edits, closing tags) must sit inside one mapped region whose construct re-reads the same, else nothing is applied and the reason is shown. Unmapped templates show "LSP unavailable", a Server Details row per template language and a disabled reason. No adapter code changed; no commands or keys added.
Verified with Ruby LSP 0.26.11 (RuboCop 1.92.1 in the bundle), Ruby 3.3.6, vscode-langservers-extracted 4.10.0, Action View/railties 8.1.4 (Erubi 1.13.1) and Haml 7.5.1 (installed for this ticket in a private gem folder for the cross-check): ERB syntax errors exactly on the template's own bytes after CRLF, non-BMP text and multiline Ruby; `Greeter.gre` completes to `greet` in an output tag inside an attribute; parameter information `greet(name, excited: <default>)` with the right active parameter (UTF-16 on a line with `𝄞`); the HTML server completes `span` in markup and closes a typed `<b>`; one Undo step each; files unchanged; Haml syntax errors, completion in `%li=` and parameter information in `#{…}`; every mapped region is Ruby Action View and Haml compile verbatim. Fixed: a template was closed in one of its servers while a typed version converted, losing a closing tag typed then (`desired()` now returns the template). Changed for files several servers hold (templates today): trigger characters are the union, diagnostics shown together; templates get no semantic tokens or inlay hints, and RuboCop/Standard problems and void-context warnings on projections are dropped. A Markdown parity test's race with the project file listing fixed (test only).
Evidence: ignored real tests `real_erb_template_editing` (8/8 after the fix, once more before merging), `real_haml_template_editing`, `real_erb_regions_are_the_ruby_rails_compiles`, `real_haml_regions_are_the_ruby_haml_compiles` (crates/code-core/tests/providers.rs) and `real_erb_template_assistance_matches_in_both_adapters` (crates/code-tui/src/parity_tests.rs, 6/6, once more before merging); fake-server replay `template_assistance_routes_through_its_projections_alike_in_both_adapters` (typed completion and Enter, Alt+Enter, Ctrl+Alt+L, Ctrl+Space, Ctrl+Z, problems drawn in both, Server Details); 4 fake-server and 9 unit tests; whole `semantics` set 148 passed; earlier real HTML and Ruby tests re-run; clippy clean; panic-site ratchets at baseline. Haml is verified with real servers in the core only, not through the adapters; Ruby LSP formats nothing for templates; in the GUI replay the caret is placed by command.
