## Answer

Merged in 82616b5 (branch work/editor-56-markdown). In the core (`markdown_authoring.rs`, `session/markdown.rs`) behind Session commands, in both adapters. Live preview: Open Markdown Preview to the Side shows the file's preview in the other pane (the source keeps focus); every edit, Undo and Redo renders off the UI thread; while the next version renders the last preview stays (never Pending) with its positions carried through the edits since, and a render for an obsolete version is dropped by version; images decoded for one version are reused. Navigation: a preview click records a position checked against the shown tab and version; Show in Source moves the caret there (or to the reading line); Follow Link goes to a `#heading` of the current draft (unsaved headings included) or opens a project file, at its heading, trying `.md`; web links are never opened (said so); Ctrl+click follows or shows in source; both in context menus and palettes. List continuation: Enter after an item continues bullet, numbered (`9.` → `10.`, `.`/`)`) and task items with indentation and blockquote, renumbering the following items that count on; Enter on an empty item ends the list; one Undo step; plain inside fences, with a selection and in other languages; several carets continue their own items. Link completion (Lenz's own, no server): after `](` or Ctrl+Space in a destination, project files and folders (escaped, `../` and `/`), and after `#` the named file's headings as GitHub anchors or the draft's own; read off the UI thread; stale, superseded and dismissed answers dropped; one Undo step. Three commands added (`PreviewBeside`, `ShowInSource`, `FollowLink`; `CommandId::ALL` 181), none bound to a key.
Fixed: a Markdown preview shown again for the same version after its content was released stayed "Preparing" for good (workers took the new request for a duplicate); each request now has its own id.
Evidence: parity replay `markdown_lists_link_completion_and_a_live_preview_match_in_both_adapters` (real keys and pointer: continuation and Undo, the popup drawn, Enter, Escape, preview beside never blanking, the context menu, typing in the preview changing nothing, Ctrl+click to a heading and a file, 30×8 and 1×1 terminals and a 1×1 GUI, End then Up, identical bytes after Ctrl+S); 8 unit and 8 session tests including `a_preview_shown_again_after_its_tab_was_released_is_made_again` (reproduced on the integration branch first). Filtered core, GUI and TUI sets pass (re-run before merging); one known timeout (`followed_rename_invalidates_source_context_hits_without_changing_text_version`, already listed) seen on the branch and on the integration branch; clippy clean; panic-site ratchets at baseline. Performance deferred to the end-of-epic campaign (user decision). Limits in docs/markdown.md and docs/editor-follow-ups.md (ticket 56): source and preview scrolling not linked; under continuous typing the preview updates when typing pauses; no keyboard preview caret for Follow Link; no outdent of a nested empty item and no renumbering after an item is ended or deleted; no reference-style or wiki links; headings inside lists, quotes or HTML not offered; anchors differ from GitHub's for headings with HTML, emphasis or entities; file suggestions need an open folder; a changed image shows after reopening the preview; native macOS, Wayland and physical terminals unverified.
