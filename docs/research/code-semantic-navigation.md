# Draft-aware semantic navigation and edited anchors

Ticket 17 binds provider target coordinates to the source identities admitted
when the RPC enters the existing writer FIFO. Foreground and hierarchy requests
capture weak version/metadata identities; replacement, cancellation, reply and
server exit retire them through the existing lanes. Deferred requests capture
only when actually enqueued. Hover and highlight do not acquire target maps.
There is at most one pending context per relevant lane per server; downstream
resolution retains the existing bounded result-owner and worker admission.
These bounds limit map generations, not the number of live open sources.

Exact-read decoding records an optional canonical naming path in immutable
SourceMeta. Drafts and worker materialization share it. Confirmed rename replaces
it with the completion's canonical path, while generic unknown renames clear it;
inactive-cache metadata rebinding updates its byte charge. This naming provenance
is neither a filesystem refresh nor Save validation. Target resolution projects
both URI spellings from exact written Documents and preserves every missing or
changed captured spelling as a blocked tombstone. Distinct identities claiming
one alias are refused. No late canonicalization, additional URI cache, provider
map lifecycle, worker pool or full-text input/render materialization is added.

Publication independently validates the target against loaded or pinned current
sources. Identical text after Undo still has a fresh identity and cannot validate
old coordinates. Cached immutable previews and the read-only saved comparison side do not become
authoritative drafts.
Peek, usages and multiple-target results retain the accepted source snapshot;
later preview and activation reuse ticket 16's exact snapshot or disk
Stamp/decoded-digest checks. Reusable hierarchy items carry their own source
identity, separately from the displayed call site's identity. Changed items or
resolution failures finish the affected node with a visible notice.

Edits transform matching bookmarks, reading-history locations and pending view
restores through the same right-biased byte transform used for view positions.
An anchor at an insertion follows inserted text; an anchor inside a replacement
collapses after the replacement. Existing content invalidation clears derived
fold/selection-expansion state and reissues current Find work. Shared commands
remain the only mutation seam, and production writable input remains gated.

Focused Session/provider checks cover cross-pane target changes before reply,
held analyzed results, same-text Undo, unrelated edits, captured Peek activation,
hierarchy item changes, canonical symlink success, alias collisions and weak
request-context retirement. A decisive held-reply test renames the canonical
file itself, installs different valid bytes at its old name, and proves the old
reply cannot navigate there. That test failed before the alias fix and passes
afterward. Cache-rebinding accounting is checked separately.

Real GUI/TUI input/render replays cover Unicode/CRLF bookmark and Back movement,
Undo, retained dirty targets, Peek switching, visible stale feedback, refused old
activation, fresh Definition and usages. Exact state and unchanged fixture bytes
are compared; anchor presentation is exercised in both appearances. Affected core
and adapter lint passes at the recorded source identities. Raw focused logs and
configuration are retained under target/perf/editor-implementation/17-core and
17-adapters in the integration checkout. No per-ticket full gate, performance
or stress run was launched; acceptance remains the next shared batch. Native
macOS, IME and physical display latency remain unverified.

Disk-only hierarchy input changes before a new provider request retain the
existing limitation recorded in [the follow-up list](../editor-follow-ups.md).
